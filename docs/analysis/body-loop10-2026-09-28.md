# Body-text gap taxonomy (loop 10), eval-dev13, 2026-09-28

Read-only analysis. Scripts and intermediate data are in `scratchpad/bl10/`: `p1.py` (exact bit-parallel LCS, sampled and unsampled), `p4.py` (run classifier), `p5.py` (tail simulation), `res3.json`, `pdftxt/`, `src/`.

**Sample.** The 15 lowest-aligned dev papers plus 10 mid-range papers (ranks 26–35: 2108.04588, 2504.09409, 2503.15734, 2511.15503, 2603.12824, 2501.17300, 2309.10334, 2508.19485, 2509.08395, 2511.22707).

**Method.**
- **Tokens.** The same tokenizer as `eval.rs::words` (`normalize_title`). Truth passes through `drop_math_lines`, as the metric does. My sampled LCS reproduces every `align` value in report.md exactly.
- **Runs.** Runs come from an unsampled difflib alignment on word sequences. Gaps separated by ≤2 matched words are merged. The run is then split at blank lines and each block is classified.
- **Three oracles.**
  1. `pdftotext` text of the same PDF: is the truth run really printed?
  2. A 4-gram index of all `.tex` files, with environment flags (figure, table, algorithm, math, front, appendix): where does the extracted run come from in the source?
  3. `tagged_lines` 4-grams: was the run over-tagged?
- **Counts.** All counts are words in runs of ≥8 words. They are unsampled, so they describe the true gap, not the reported score (see section 0).
- **Sample totals.** 37,809 extracted-only words and 103,037 truth-only words.

## 0. Two metric effects, kept separate from the run classes

### 0a. `sample_evenly` at `MAX_ALIGN_TOKENS = 12_000` (eval.rs `align_counts`)

When either side has more than 12k words, both sides are subsampled at *different* strides. The subsampled sequences no longer correspond, and the LCS collapses.

| Paper | Sampled (reported) | Exact |
| --- | --- | --- |
| 2503.13415 | 0.489 | 0.932 |
| 2305.13843 | 0.567 | 0.906 |
| 2510.07065 | 0.620 | 0.880 |
| 2608.28714 | 0.684 | 0.887 |
| 2511.15503 | 0.713 | 0.796 |
| 2603.05575 | 0.313 | 0.391 |

- **Dev mean.** 0.738 sampled vs **0.769 exact**.
- **Exact recall and precision.** 72.2% / 83.0%, against the reported 68.7% / 77.5%. The report's `body words m/e/t` columns are sampled values, capped at 12000.
- **Fix (eval.rs `align_counts`/`lcs_len`).** Drop the sampling and use a bit-parallel LCS (Allison–Dix/Hyyrö: `U = V & M[c]; V = (V + U) | (V - U)`).
  - Cost is O(n·m/64). In Python on big ints it ran all 60 papers in about 4 s total.
  - In Rust, use `Vec<u64>` words with carry, or the `bitvec` crate.

### 0b. Truth continues past the references; extracted stops there

This is class 1 below, and it is by far the largest gap.

**Totals.**
- **Truth-only:** 103,037 words; class 1 alone is 84%.
- **Extracted-only:** 37,809 words. Untagged figure, table and math material (classes 2, 5, 6, 11) is 24,049 words, 64%.

**Dev60 scale of class 1.** Truth after the last ≥20-word match totals 124,394 of 578,666 truth words (21.5%), and 31 of 60 papers have a tail over 500 words.
- Cutting truth at that point raises dev from 0.738 to 0.846 (exact LCS: 0.769 to 0.871).
- On holdout13 (23 dumps) it raises 0.774 to 0.869 (exact 0.786 to 0.876). There, 2505.11298 alone goes from 0.495 to 0.933.
- **These are upper bounds.** Cutting truth also discards any truth tail that was genuinely lost.
- **Where the tail sits.** For the 20 sample papers I checked, 97% of the tail words sit after the first reference heading in `pdftotext`. The rest are in 2510.26824 ("Notes and references" heading not matched by my check), 2602.17690 (2.1k) and 2511.22707 (1.3k).
- **Recommended fix: extracted side.** Faithful reading order means the appendix must be emitted.
  - In `body_only_text`, stop at the reference heading but resume at the first body-like page or heading after the reference list ends ("Appendix", "A …", "Supplementary Material(s)", or a page where parsed references stop).
  - Stop using `break` on every later page.
  - The pipeline should mark the reference list's end, not only its start.
- **Alternative (not recommended): truth side.** Cut `latex_refs.rs::body_text` at `\bibliography` / `\printbibliography` / `thebibliography`. It raises the score without improving fidelity.

### 3. Math tokenization mismatch (both sides)
- 2504.09409 (T residue): `"i = 1^m ( c_i ( x ) - c_i ( y ) ) c_i ( x ) + ( c_i ( y ) +_i^k ) ( c_i ( x ) -c_i ( y ) ) _2 &L_f x-y_2+ …"`
  - This is `align` content with `&` surviving in truth, so the environment was not removed. Check for starred or custom align-like environments.
- 2108.04588, a PDF glyph-decoding problem: EXT `"λx + (1 � λ)y ⋆ with λ 2   and\nkp � z k < kp � x k"` vs TRUTH `"x^+(1-)y^ with and p-z^<p-x^"`.
  - CMSY/CMEX glyphs decode as ASCII look-alikes: ∈→`2`, ‖→`k`, {…}→`f…g`, and −→U+FFFD.
  - 61 occurrences of `" 2 N"` in that paper.
  - Across dev60 there are 1,150 U+FFFD in extracted bodies in 34 papers, and 851 page warnings mention unmapped codes. The largest counts are 2108.04588 (259), 2504.10389 (252), 2506.03828 (112), 2509.17930 (89) and 2506.23487 (86).
- 2504.09409 (truth-side label noise): EXT `"Lemma 4.4. Under Assumptions 2.1–2.4 and Assumption 3.1"` vs TRUTH `"Under Assumptions – and Assumption"`.
  - `\ref` numbers become empty and theorem-environment labels ("Lemma 4.4.") are absent from truth.

Fixes:
- eval.rs: drop inline-math-like tokens on both sides, e.g. single-character tokens, tokens with `_`/`^`, and Greek letters. That is equivalent to comparing "prose words only".
- latex_refs.rs: emit `\ref`/`\eqref` as a placeholder that eval drops, and emit theorem labels.
- lopdf font decoding: map built-in CMSY/CMMI encodings.
- **Only about 6% of this bucket is non-math**; see class 15.

- 2508.19485, lines of two columns interleaved: `"inwise\ndense mask prediction for blurry, deformable, and temdustrial\nmonitoring applications.\nporally unstable gas plumes. Therefore, directly adopting…\n2 Related Work\nsegmentation.\nBeyond visual enh…"`

## 3. Tagged-line over- and under-tagging per role (25-paper sample)

**Over-tag** counts `tagged_lines` entries of ≥4 words whose token sequence occurs verbatim in the truth body. This is a lower bound, because entries are cut at 160 characters and lines under 4 words are skipped. Only 2601.09974 hits the 600-line cap in dev60, and it is outside the sample.

| Role | Tagged lines | Over-tagged lines (verbatim in truth) | Over-tag words | Truth-only runs matching tagged text | Under-tag: extracted-only words that belong to this role |
| --- | --- | --- | --- | --- | --- |
| front | 499 | **105 (21%)** | 1,136 | 1,607 (+869 head-of-body in PDF) | 661 (highlights page, affiliation footnotes) |
| furniture | 1,030 | 0 | 0 | 0 | ≈0 real (the 672 classified are figure/table text) |
| figure | 2,039 | 17 (0.8%) | 85 | 0 | **12,979** (11,486 graphics + 1,493 numeric) |
| caption | 796 | 12 (1.5%) | 80 | 90 | 2,944 |
| table | 1,640 | 20 (1.2%) | 94 | 8 | **6,284** |
| algorithm | 55 | 0 | 0 | 0 | about 400 (2603.05575 algorithm steps, 2511.15503 code listing) |
| toc | 48 | 0 | 0 | 17 | 151 (2503.13415 TOC with dotted leaders, partly duplicated) |
| (math, no role) | — | — | — | — | 4,786 display fragments |

**Summary.**
- Tagging is precise: figure, table, caption and furniture all have ≤1.5% over-tag.
- The weak spots are `front`, which over-tags abstracts and first paragraphs, and recall: figure, table and math text are left untagged, about 24k words.

## 4. What to do first (expected effect)

1. **eval.rs: resume the body after the reference list.**
   - Class 1 is 84% of the truth-only words.
   - Upper bound: dev 0.738 to about 0.85, holdout 0.774 to about 0.87.
2. **eval.rs: exact LCS instead of `sample_evenly`.** Dev goes from 0.738 to 0.769 by itself, and the effect grows once appendices make both sides longer.
3. **regions.rs figure, table and math recall** (classes 2, 5, 6, 11, about 24k words, 64% of extracted-only):
   - rotated text goes to figure/table;
   - short-line clusters over graphics go to figure;
   - symbol-dense math lines get a math role.
4. **Caption regex for `Fig. N Word` style** (eval.rs + regions.rs).
5. **Front-matter end** (regions.rs).
6. **reading_order.rs**: gutter-straddling line fusion and the full-width to 2-column y-split.
7. **Small truth-side fixes** in latex_refs.rs:
   - dotted `\input`;
   - the RSC affiliation block;
   - `\ref` placeholders and theorem labels, or an eval.rs rule that drops math-like tokens on both sides.
