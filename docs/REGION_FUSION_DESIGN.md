# Region evidence and fusion design

Focused foundation tracking: [#196](https://github.com/benpshore/pdftextract/issues/196).

This is a proposed native-engine design for [#181](https://github.com/benpshore/pdftextract/issues/181), with service admission owned by [#182](https://github.com/benpshore/pdftextract/issues/182). It is based on read-only inspection of main **`e27e1fb28a5b40dbca7f517c6fe396e6f11ed4ec`** and PR #175 **`baafb472873750e7e84d32c3c8e6fa7a680e37db`**. References below are pinned to those commits, rather than moving branch heads. No parser, runtime, workflow, production schema, ledger or production Cargo change is specified as already delivered here.

The first implementation boundary is an **opt-in, production-unwired evidence foundation** in `experiments/region-evidence/`: preserve immutable extraction artifacts, validate their identity and evidence references, retain alternatives, and abstain from choosing a replacement. It must not select longer text, manufacture confidence scores, infer semantic correctness from a successful validation, or expose a fusion promotion API. Actual region selection, native adapters, crash recovery, and accuracy qualification are later gates. The experiment's README and tests define its implemented API; the rest of this document describes requirements for later work, not current capabilities.

## 1. What exists, and what is missing

Main already defines source identity as a complete-byte SHA-256 and extraction identity as source hash plus backend/configuration/schema. Its `Span` stores NFC-normalized decoded text, optional geometry/font/size, and backend sequence; `Line.spans` indexes the page's span array. It does **not** contain PDF object identifiers, original encoded glyph bytes, mapping witnesses, independent correctness labels, or per-span backend identity. `ExtractionResult` carries one backend. These shared shapes are unchanged at the inspected PR #175 commit. A span's `seq` is an ordering observation, not a globally stable evidence ID. [Main schema:18–87][main-schema-spans], [main schema:344–375][main-schema-result].

PR #175's opt-in native cascade is `lopdf → PDFium → MuPDF → Poppler`; candidates reread the requested page range. Its guards check source/hash, page coverage, status, decoded counts, and known URI/figure evidence. It still replaces a whole pass. MuPDF/Poppler alternatives must improve complete-page count, then mapping uncertainty, then decoded character count; PDFium replacement follows the regression guards without that additional ranking. It cannot reject every equally long wrong transcription or preserve its in-memory baseline after a later native crash. [Fallback contract:10–62][fallback], [pipeline routing:428–575][routing], [pipeline quality/guards:619–760][quality]. This design does not reuse that ranking as a truth test.

`DocumentSession` opens complete immutable bytes and provides `page_text(page)`. There is no region/crop extraction operation. PDFium eagerly extracts every page during `open`; Docling text parses requested pages. Therefore **region routing describes evidence and decision scope; it does not imply region-only computation**. Each attempt must report actual work performed and be charged accordingly. [Backend traits:63–94][traits], [PDFium:139–151][pdfium-eager], [Docling text:17–34][docling-text].

Existing `regions.rs` tags line roles after cleanup; it does not provide a stable region identity, source-to-region ownership map, or conflict arbitration. Reading order and cleanup derive text from spans, while region tags are heuristics. Preserve both extraction evidence and the existing derived baseline; do not reinterpret `body`, `table`, or a caption band as independently labeled ground truth. [Regions:1–13][regions], [pipeline:820–861][derived].

`Complete` means no supported detected extraction gap. It is not a proof of exact text or reading order. Keep run execution outcome, extraction coverage, and adjudication outcome separate. [Main repair limits:54–62][main-limits], [schema status derivation:151–165][status].

## 2. Non-negotiable invariants

1. **One immutable source.** Every artifact, attempt and region belongs to the same complete source SHA-256 and byte length. Original path/inode/mtime are observations. Read a verified source snapshot once for the future supervisor; all candidates receive that same snapshot, never a newly resolved user pathname. Reject an artifact from another source even if its text/pages look identical. Never modify the input or let output, ledger, journal or staging names alias it. Current acquisition checks before/after read are useful but are not a persisted cross-attempt snapshot. [Acquisition:118–184][acquire], [source/output protection:67–82][worker-publication].
2. **Baseline is immutable evidence.** Preserve exact serialized baseline artifact bytes and their digest, original span text/geometry/sequence, lines/text, URI actions, figure metadata and available payload hashes, all warning levels, and backend identity. A selected view references evidence; it never overwrites it. Exact artifact hashing is byte hashing, not a claim that a JSON reserialization is identical. The original PDF remains the source for byte-level evidence that the current schema does not expose.
3. **Local identity is explicit.** An evidence locator includes artifact digest, page number, typed collection and array index. A future subspan locator additionally declares its unit and boundaries; byte offsets must be valid UTF-8 boundaries, while scalar indices must not be misrepresented as glyph indices. Optional PDF object/font/code identifiers are retained only when an adapter actually exposes them. No generated locator may masquerade as an original PDF identifier.
4. **Page ownership cannot move.** Bind every region and evidence item to one selected physical page. Validate page sequence, uniqueness, range and total-page count; do not compare only sets or zip a truncated sequence. Future runtime candidate attempts may deliberately cover a subset of selected pages; their manifest declares that exact subset and the artifacts must match it. The foundation is narrower: every candidate declares the same ordered page selection as its baseline. An unchanged baseline page does not disappear because no alternative was attempted.
5. **Unknown stays unknown.** A missing bbox, native object identity, font field, runtime fingerprint, mapping method or verified transform stays absent. Candidate similarity, grammar, token count, engine majority, HTTP success and a backend's `Complete` flag cannot fill it in. No numeric confidence is generated without a defined, independently calibrated measurement contract; the foundation has no confidence field or score-based selection.
6. **Evidence types stay separate.** Native decoded text, existing hidden OCR text, newly inferred OCR, spatial layout, image placements/pixels, raw annotation actions, and bibliographic enrichment have different meanings. A geometry/layout operation cannot silently become text recovery; a service's semantic text cannot become native glyph evidence. Copying the same parser's output through a second adapter is not independent corroboration.
7. **Every disagreement is retained.** Preserve rejected and unmatched candidates with the reason, warnings, attempted engine identity and actual work. A future promotion requires a typed decision, evidence references, a qualified verification rule, and a reversible mapping back to the baseline. No longest-text fallback, arbitrary candidate tie-break, deletion of source warnings, or silently synthesized third transcription.
8. **No collateral loss.** A text decision does not drop or rewrite unrelated links, images, layout hypotheses or source text. Repeated placements remain distinct even when they share URI/pixel hashes. In a future consuming view each baseline text atom has exactly one owner, with explicit replacement or unchanged disposition; alternative hypotheses may overlap, but competing promoted edits may not consume the same atom.

## 3. Evidence foundation and future contract

The standalone Rust foundation is deliberately narrower than runtime fusion. It can bind an artifact store's immutable `ExtractionResult` JSON bytes to a sidecar; check source/hash/length, backend identity, page selection and typed locators; expose retained baseline evidence; and retain candidate alternatives with abstention. It cannot establish that a producer correctly extracted a PDF, that two boxes align, or that a candidate repaired a glyph. A hash proves identity/integrity only relative to the supplied bytes. A `ProducerDeclaredPdfUserSpaceUnrotated` frame allows describing that artifact's own geometry; it is not a verified cross-engine transform.

The following are the **future runtime contract**, not promises that every field is in the foundation:

| Record | Required meaning |
| --- | --- |
| Source snapshot | Complete-byte digest/size; retained immutable snapshot identity; source observations; private access/lifecycle information. Passwords and credentials stay outside serialized provenance. |
| Attempt | Unique attempt ID; exact requested page selection; actual observed/parsed pages; outcome; start/end and work measurements; extractor, adapter, build/configuration, runtime/provider/model identities; warnings; artifact digests; remaining budget. Missing runtime identity is explicit. |
| Artifact | Exact payload bytes, digest, byte length, format/schema and producing attempt; immutable baseline and alternative outputs are separate artifacts. Preserve native payloads when a normalized projection loses detail. |
| Region | Source/page; region-builder policy version; deterministic ID derived from the baseline artifact and explicit evidence membership; context evidence separate from consuming membership; optional observed boundary and frame. |
| Evidence item | Artifact-local locator; evidence kind and granularity; exact producer text/value and optional geometry; dependencies on originating evidence; original frame and explicit transform if actually captured. |
| Correspondence | Baseline and alternative memberships; geometric/text alignment observations; unexplained omissions/additions; ambiguity and reason. A correspondence is not a selection. |
| Verification record | Qualified rule/version; cited source/render/adjudication artifacts; scope and observed result; unresolved limitations. An untrusted producer's `verified: true` is insufficient. |
| Decision | `retain_baseline`, `retain_alternative_unselected`, `unresolved_conflict`, or a later gated typed promotion; supporting verification references; old/new memberships; reasons; policy identity. |
| Derived view | Ordered references to selected evidence and explicit presentation-only transformations; independent view/policy identity; complete membership accounting; links/images and uncertainty side channels. |

Current native providers transform their `bounds`/`to_pdf` geometry into `PageText` and do not retain that original transform in schema 5. MuPDF/Poppler's ABI has structured blocks/lines; Docling text supplies cells without font fields; PDF Oxide supplies characters. Retain those granularities. Do not split a word/line box into invented equal-width character boxes to make providers appear comparable. [Native payload/transform:417–567][provider-transform], [Docling text fields:19–30][docling-text], [Oxide contract:20–43][oxide-contract].

Keep the foundation outside production `src/schema.rs`, `src/pipeline.rs`, parser modules, workflows, main Cargo manifests and ledger migrations. Future schema/ledger integration needs its own reviewed versioning and migration plan. A fused derived view must have an explicit fusion-policy identity plus references to every contributing extractor; it must never claim that a blended result was produced by `lopdf` or another single backend. Existing baseline result keys remain valid.

## 4. Region construction and routing

The future pipeline first persists the cheap lopdf baseline for all selected pages. It then identifies **suspect evidence**, not simply low text counts: retained unresolved mapping positions, parser/resource warnings, invalid/missing geometry, source/render disagreement found by a qualified check, or an explicitly requested layout view. An empty page can be blank or artwork; a large raster with little text is an OCR candidate observation, not proof of missing source glyphs. Current scan/mapping thresholds are routing heuristics, not accuracy scores. [Router:150–220][router-observations].

Build bounded regions from baseline evidence membership and observed geometry. Keep the builder versioned and deterministic. Prefer a smallest coherent span/line group whose boundary does not divide a source atom, combining connected uncertainties when they share font/content context. A bbox is a search envelope, not exclusive ownership: columns, annotations and figures may overlap it. Track a separate context halo for matching; context text cannot be copied into the output again. If a warning cannot be localized, use an explicit page-scoped unresolved region instead of guessing coordinates. Keep evidence without geometry in an unpositioned collection.

Native APIs currently require at least page-level work. Group requests for the same engine and page selection so one page attempt can serve several regions; do not rerun an engine for every small box. Retain the full attempt artifact, but only consider evidence linked to the target region for a future decision. A candidate span that crosses a region boundary requires validated membership splitting or expansion of the adjudication scope; never clip its text merely by a center-point test. Cross-column and cross-page joins require explicit order evidence and remain unresolved if ownership cannot be established.

| Need observed in the baseline | Eligible existing component | Restriction and stopping rule |
| --- | --- | --- |
| Ordinary mapped native text | lopdf | Keep baseline. Installed alternatives alone are not a reason to rerun. |
| Selected simple Type1C mapping gap | Existing optional pdf-extract/CFF helper | Helper evidence belongs to the lopdf attempt; it is not an independent whole-document parser. Explicit existing mappings win. |
| Unresolved native mappings or content interpretation | PDFium, then configured MuPDF/Poppler candidates | Each engine at most once for an identical work key. Preserve unresolved original mappings; successful API return or absent warnings does not verify the specific character. |
| ActualText or a localized title/text disagreement | PDF Oxide candidate | Preserve declared semantic text separately from painted text. Its demonstrated ASCII recovery and Unicode mojibake forbid global preference. |
| Spatial forms/table presentation | LiteParse layout over originating PDFium spans | A layout hypothesis only. Preserve exact origin dependencies. Character-multiset retention is necessary but cannot prove word order or cell topology. |
| Alternate word-cell segmentation | Docling text | Candidate text/layout with native side evidence; no models/OCR. It lacks font fields and password input. Its scalar guard is not a promotion rule. |
| Image-only/mixed scan requiring new recognition | Future admitted Docling layout/OCR lane | Full Docling remains blocked in supervised extraction. Admission needs runtime/model pins, process containment and measured page ownership; retain image and OCR hypotheses separately. |
| Scholarly fields or reference enrichment | Explicit configured GROBID service lane | No automatic upload. TEI fields/coordinates stay semantic evidence with endpoint/version/options and raw TEI ranges; they do not replace native glyphs or raw PDF URI actions. |

The helper/backend boundaries and pinned capabilities above are documented in [the inspected handoff:66–80][handoff-components], [LiteParse source:1–13][liteparse], [Docling text/layout split:17–55][docling-text], and [GROBID:45–71][grobid-evidence]. The five-paper Oxide comparison records one reference-title improvement alongside lower body/metadata scores; it is direct evidence against whole-document preference. [Oxide measurements:47–74][oxide-measurements].

No region engine registry should pretend that these are all statistically independent. LiteParse depends on PDFium's text; Docling text retains lopdf side evidence; full Docling also depends on PDFium in this pinned implementation. Record a dependency graph so the same underlying evidence cannot be counted multiple times.

## 5. Correspondence and arbitration

Use a staged, abstaining decision procedure:

1. **Admission:** validate the exact immutable source, page ownership, attempt identity, successful complete artifact framing, declared evidence kind, finite geometry and membership locators. Reject malformed/stale/cross-source evidence before any matching. Failed/crashed attempts may contribute diagnostics, never a truncated success artifact.
2. **Frame check:** retain the backend's native frame, CropBox/MediaBox origin, rotation, units and actual conversion to unrotated PDF user space. Matching width/height alone is insufficient. Require validated conversion before spatial correspondence. Missing frame information leaves alternatives unmatched. Never fit a transform from conveniently similar strings and call it source geometry.
3. **Correspondence:** compare observed geometry, native granularity and exact text with declared normalization solely for comparison. Record one-to-many/many-to-one matches explicitly. Do not collapse duplicate painting, repeated headers, two identical DOI labels, or hidden OCR into one occurrence merely because text matches. An unexplained candidate-only span is additional evidence, not automatically missing baseline text.
4. **Verification:** separately evaluate transcription, order, layout, annotations and figures. Two engines agreeing or a candidate being longer establishes disagreement/agreement evidence only. Native mapping recovery needs a retained, checkable source mapping witness or independently adjudicated target evidence under a qualified rule. Current `Span` cannot supply such a witness; until an adapter does, automatic changed-text promotion remains disabled. Rendered adjudication is scoped to what is visible; PDF semantic assertions require their own source inspection.
5. **Decision:** select nothing on ambiguity. Keep the baseline plus unselected alternatives and an unresolved reason. A future qualified decision may select a native transcription, layout relation or supported semantic alternative only for its explicit scope. It cannot silently concatenate fragments into a novel transcription, replace neighboring good text, infer punctuation, or remove uncertainty outside that scope.
6. **Derivation:** compute a separate selected view from preserved evidence. Recompute order/chunks/metadata/citation derivations only for the view and record their source dependencies; never mutate the baseline's derived fields. Source spans remain inspectable alongside any presentation whitespace, hyphenation or normalization. A global order change needs its own qualification and cannot be hidden as a local text edit.

Example: a page has correct left-column prose and an unresolved right-column font. MuPDF proposes text for the right column but omits a DOI link. Keep both complete artifacts. The baseline's left-column text and annotation are retained regardless of the candidate's text; the candidate's right-column spans remain unselected until their mapping and ownership are verified. Neither longer total page text nor matching scalar counts justify replacing the page. A later valid right-column promotion references exactly the replaced baseline atoms and leaves the URI occurrence untouched.

For links, preserve raw action target, placement and any known URI base context separately from displayed labels or normalized DOI. Never fetch targets during extraction. For figures, retain placement, kind and available pixel hashes; a model box is not exported image bytes. Identical URI/pixel content may share storage, but each placement retains occurrence identity. Existing annotation union is useful precedent, with an explicit coordinate-frame guard; it is not proof of exhaustive URI recovery. [Routing review:128–165][evidence-boundaries].

Status must remain conservative. Unresolved source warnings stay in baseline/attempt history. A future verifier may mark a specific issue resolved in a derived view with evidence; it cannot erase it from the source record or infer page completeness from one repaired region. Global opaque backend uncertainty, unverified selected content, an unattempted required region, or a rejected frame prevents a claim of independently complete coverage. A failed optional attempt is recorded separately from whether usable baseline text exists. This avoids calling a completed worker a completed transcription.

## 6. Budgets, cancellation and crash persistence

The current CLI contains a whole extraction job in one disposable worker. A hard native crash or deadline kills all in-memory passes. Current publication has handled-failure rollback but no restart journal and no crash-atomic transaction across files and SQLite. A design document or offline artifact store does not change that. [Fallback crash boundary:20–30][fallback], [publication:27–39][publication-crash].

The future execution model requires a supervisor with a durable manifest and **separately supervised provider attempts**:

1. Acquire and hash one private immutable source snapshot under the job budget. Record source identity and selected pages. Stage baseline output in a private namespace, validate its complete framing/identity, sync the artifact and directory, then atomically record a `baseline_ready` manifest referencing its digest. No alternative begins before this checkpoint is durable.
2. Record `attempt_started` before launching a candidate; use a distinct process and private output artifact. Install existing platform limits, explicit trusted runtime paths and thread restrictions. Pass the same immutable snapshot, verify the returned source identity, and never let a candidate write into the baseline artifact directory.
3. Validate a completed candidate inside a limited process; sync it before recording `attempt_finished`. A receipt/reference is usable only if its referenced bytes and declared identity revalidate. Reject truncated JSON and abandoned temporary files. A returned error, signal, timeout, cancellation or missing receipt changes the attempt outcome and preserves the baseline checkpoint.
4. On supervisor restart, reconcile only fully committed manifest generations and artifact digests. Mark interrupted attempts as interrupted; do not automatically retry native work or adopt arbitrary orphan files. Recovery must not trust a source pathname that has changed. A retained snapshot/artifact policy must define private access, cleanup and disk-exhaustion behavior.
5. Stage selected views independently and publish via a versioned result identity. Existing publication can report `publication_unknown`; do not turn an uncertain ledger/export outcome into success or blindly repeat it. Inspect durable receipts/artifacts before retry. Source and prior outputs remain immutable.

These are requirements for later runtime work. The standalone in-memory evidence foundation is **not** the manifest, durable store, supervisor or restart implementation.

Use one end-to-end job deadline, covering snapshotting, baseline, alternatives, matching, validation, journal writes, publication and delivery. Do not reset a full document deadline for each engine. Budget includes actual eager work and candidate-output processing. Only start an alternative if configured admission rules leave enough measured reserve to persist and return baseline evidence; reserve values need measurements on the target runtime, not an invented percentage. An insufficient budget yields a recorded skipped/deferred region and retained baseline.

Keep explicit attempt/work keys and a finite policy-selected set of eligible engines; no retry loop and no engine revisits for the same work. Charge spatial matching comparisons, text alignment and retained alternatives to explicit work/memory/output budgets so dense pages cannot cause unbounded pairwise matching. Exhaustion abstains over the complete affected scope; a searched prefix is not a valid winner. No new arbitrary file-size/page-count rejection follows from this design. Large input can fail a real resource constraint, which must be reported with surviving evidence.

The inspected CLI defaults are 60 seconds/document, 1,024 MiB virtual-address-space growth and one worker, with no default source/output byte cap. Those are existing controls, not achieved RSS, latency or arbitrary-size guarantees. Peak resident memory and aggregate concurrent-process usage must be measured separately. [Worker limits:11–53][worker-limits]. New worker topology needs an explicit aggregate budget; duplicating a per-worker allowance across attempts must not silently multiply the job's permitted memory.

Cancellation stops new attempts, kills/reaps owned workers and persists an interrupted/cancelled job outcome where possible. Already durable baseline evidence remains recoverable, but cancellation must not publish a new success claim. Total budget exhaustion may prevent immediate baseline delivery; restart retrieval is a separate operation. Cancellation of a local GROBID client cannot prove remote work stopped. The current full Docling lane remains excluded until its child/model/runtime behavior is qualified. [CLI cancellation:55–82][worker-publication], [Docling admission:36–55][docling-text].

## 7. Acceptance gates and evidence requirements

No existing report demonstrates region-fusion accuracy. The native validator checks cohort/identity/status completeness and intentionally does not gate extraction accuracy; its tests accept a zero reference-recall diagnostic. Existing body alignment omits non-body roles, math-heavy lines, markers and all-digit tokens. These metrics remain useful diagnostics, but cannot certify a repaired figure label, table, equation, citation occurrence or exact region transcription. [Validator:22][eval-validator], [validator test:33][eval-validator-test], [body metric:205][body-metric].

| Gate | Required evidence before progression | What a pass establishes |
| --- | --- | --- |
| A. Foundation integrity | Exact-byte artifact digests; source/page/backend checks; validated collection indices; round-trip preservation; independent rejection cases for mutated bytes, dangling refs, foreign source/page, duplicate IDs, malformed geometry and unknown required contract version. No promotion function. | Evidence references and retention behave as specified. No accuracy, runtime isolation or persistence claim. |
| B. Actual engine adapters | Same immutable PDFs and selected pages through every engine admitted by the policy; actual artifacts/identities, source/output hashes, all failures/skips, native geometry and preserved raw values. Required engine/runtime absence must fail this qualification rather than return early. | The real selected binaries execute and preserve the declared contract. Mock/synthetic records alone do not qualify an adapter. |
| C. Correspondence and semantic acceptance | Frozen independently adjudicated holdout; baseline, each engine and derived view evaluated on the same inputs; region membership/order and occurrence-level annotation/citation truth; per-region gains, regressions and abstentions; no collateral loss. | Only the measured policy/corpus/target qualifies. Agreement or higher average body alignment is insufficient. |
| D. Operational behavior | Real provider crash, resource kill, cancel, output backpressure, interrupted journal write and publication ambiguity after a durable baseline; restart artifact verification; source/path/alias immutability; actual time and memory observations. | Previously committed baseline survives the tested failures and the job does not claim uncommitted success. |
| E. Deployment/release | Exact final revision and dependency/runtime/model fingerprints, locked reproducible native builds, configured Linux x64/ARM64 and macOS ARM64 runs as applicable, unchanged mandatory containment checks, and owner review of #181/#182 admission. | The named build/runtime is qualified for the measured lane. Native tests do not deploy a service or browser artifact. |

Ground truth must include **rendered PDFs**, not merely another extractor's text or source-record XML. Retain source hash; renderer/build/font environment; page and crop; resolution and raster digest; independent transcription/order annotations; reviewer/adjudicator provenance; and clearly labeled genuinely ambiguous characters. Inspect exact punctuation, digits, diacritics, ligatures, symbols, superscripts, math, rotated/cropped text, figure labels and table content. Separate development/tuning material from holdout truth; do not rewrite truth to match the new policy.

Render truth and semantic source truth are separate tracks. An `/ActualText` string can intentionally differ from painted glyphs; hidden OCR may be invisible; a DOI annotation target cannot be inferred from a rendered label. Retain both visible transcription and direct PDF semantic/action evidence, declare the consumer's requested representation, and score each against its appropriate truth. Link truth needs raw target and placement occurrence; image truth needs real placement/pixel availability; table truth needs cell topology and content, not attractive Markdown. Reading order needs annotated relations, and citation truth must check the specific occurrence and correct target, including non-citation negatives. The existing marker diagnostic accepts a target cited anywhere, which is too weak for this gate. [Marker metric:2701][marker-metric], [ActualText discrepancy:68–74][oxide-measurements].

The corpus must exercise clean born-digital controls; broken/missing ToUnicode and CFF/CID/ActualText cases; multilingual/RTL and rotated/cropped pages; multi-column and cross-column content; repeated/overprinted/hidden text; mixed scan/native pages; figure/caption and dense vector regions; merged/continued/rotated tables; encrypted/password cases; repeated URI placements/relative targets; partial page selections; pathological valid dense inputs; and wrong-text candidates of equal or greater length. A mixed-engine acceptance example must demonstrate different justified contributions on the **same document**, not simply choosing one whole engine per document. Failure/abstention controls must show useful baseline retained when no verified improvement exists.

Report exact fully correct chunks as required by the engine's existing stated protocol, plus diagnostic character/word errors, page coverage, region ownership, order/cell/link/figure errors, and baseline-relative gains/losses. Include all selected documents and attempted regions in denominators; preserve failure and incomplete categories rather than evaluating only successful promotions. The gated qualification cohort must have no unexplained corruption of baseline evidence or accepted wrong replacement. Broader performance/accuracy targets require prespecified, independently reviewed cohort sizes and thresholds; this design invents no confidence percentage or success rate. [Engine accuracy contract:84–89][accuracy-contract].

Existing evidence is a starting point only: the independently rendered PDFium mapping fixture checks a narrow known discrepancy and Partial status; its runtime tests can skip without a library. MuPDF/Poppler tests are opt-in adapter fixtures. The five-paper Oxide comparison is unoptimized and selected for difficulty. Required qualification records must say which engines actually ran and retain exact build/runtime hashes; a configured workflow, ignored test, or local mock is not a pass. [PDFium fixture:6][pdfium-render-truth], [PDFium runtime check:12][pdfium-skip], [native provider tests:14][native-tests], [Oxide measurements:47–85][oxide-measurements].

Measure cold and warm release-build latency, end-to-end time, actual pages parsed, source/output/journal bytes, peak RSS and relevant address-space limits, per-stage/attempt durations, cancellation delay and failure outcomes on the same hardware. Report baseline and incremental cost alongside correctness. Existing 30 ms/M1 and exact-chunk goals remain goals; diagnostic timings do not certify them. [Main engine measurements:37–62][main-measurements].

## 8. Work boundaries

The foundation may land independently because it does not alter runtime results. Next work under #181 is artifact adapters, explicit frame/source witnesses, durable separately supervised attempts, region correspondence, and a qualified arbitration policy—in that order, each with the gates above. #182 owns native/model/service provisioning and authenticated durable job delivery. Full Docling and GROBID require their separate deployment evidence; no automatic remote transfer is introduced here. The inspected handoff explicitly distinguishes native TPE from the private browser Site, which uses another artifact. [Handoff:7–12][handoff-runtimes], [#181 acceptance export:22–29][epic-native], [#182 required work:19–26][epic-services].

Release/bibliography ownership for PR #175 stays with its existing owner. This design does not merge, close or duplicate those work items, mutate GitHub, change release policy, or qualify the current PR for publication. Remaining blockers to actual fusion are the absent production provenance/frame adapters, a durable cross-provider supervisor, verified region arbitration, and the actual multi-engine/rendered-truth acceptance evidence. The foundation's passing contract tests cannot remove those blockers.
