# Browser storage lifecycle contract

Work tracked by [#186](https://github.com/benpshore/pdftextract/issues/186) under epics [#179](https://github.com/benpshore/pdftextract/issues/179) and [#178](https://github.com/benpshore/pdftextract/issues/178). This is repo implementation for the web runtime. It does not deploy the Site or change native TPE. The integration base is draft PR #175 at `baafb472873750e7e84d32c3c8e6fa7a680e37db`.

| Action | Data affected | Confirmation and recovery |
| --- | --- | --- |
| Remove from queue | One local queue entry and its next IndexedDB checkpoint | Cancel and settle active attempts first. Confirm discarding local-only source/results. Never call DELETE implicitly. Saved server documents survive. |
| Clear saved copies | Redundant File/decoded-source/result fields of `phase: saved`, `record` present, `savePending` false items in this owner's IndexedDB snapshot | The reusable control explains scope before clearing. Drafts, stopped/failed/active imports and unsaved results remain. No server or OPFS operations. |
| Delete saved document | Owned D1 document metadata; its R2 original/results/assets; matching upload receipts and unfinished multipart sessions | Explicit per-document confirmation. The API needs `confirmDocumentId` matching the path. A tombstone retains only ID and owner to block late commits. No test uses a deployed bucket. |

## Wiring for the UX integration owner

`web/app/workspace.tsx` is intentionally unchanged in this branch. See `BATCH_CONTROLS.md` for the reusable intake/progress/actions interfaces.

1. Render `DeleteStoredDocumentButton` for the selected saved record. Its confirmed callback calls `deleteStoredDocument(record.id, {confirmDocumentId: record.id})` from `lib/document-client.ts`. Disable deletion for a record with active local work or explicitly cancel/settle it first. On success remove that record from local library/selection, remove or mark all matching queue entries, and checkpoint. Keep unrelated imports. On failure retain retry access; HTTP 503 explicitly says library removal succeeded but byte cleanup still needs a retry. The client exposes that state through `StoredDocumentDeletionError.libraryRemoved`. The integrated workspace invalidates stale reads immediately, checkpoints a named pending cleanup action, and restores an explicit retry after ordinary reload. It never deletes automatically during recovery. A generic failure before confirmed library removal releases the local writer lock.
2. Render `ClearCachedFilesButton`. Its callback first awaits a fresh checkpoint, then calls `clearSavedWorkspaceCache<Snapshot>(userId)`. This rejects on storage errors; show the message. Do not replace a changing in-memory queue wholesale with an older returned snapshot. Strip only confirmed saved copies from the current queue, or settle updates around this operation, and preserve current pending sources/results. The returned snapshot is useful for stable UI state and reload.
3. `writeWorkspace` and clear share an owner write sequence. IndexedDB v2 adds a per-owner `cachePolicies` store; saved IDs cleared here remain stripped in later checkpoints, including a stale tab's checkpoint. The clear transaction reads the latest persisted snapshot. This is **not** general multi-tab queue conflict resolution: the legacy whole-snapshot writer can still overwrite unrelated newer queue changes from another tab. Coordinate an exclusive active workspace or implement revision/merge semantics before claiming that capability.
4. `DELETE /api/documents/:id` is authenticated with the existing owner/same-origin check and requires JSON `{ "confirmDocumentId": ":id" }`. Success is 204. Unknown/foreign IDs are 404 with no bucket access; missing confirmation is 400; incomplete cleanup is retryable 503. Deploy migration `0002_document_deletions.sql` before this API code. This task does not apply it to a deployed database.

## Boundaries and race handling

- IndexedDB stores structured-cloned browser File/Blob recovery data by owner. Quota/eviction can still interrupt recovery; this is not background processing or durable multipart resume.
- OPFS `tpe-import-tmp` holds one expanded archive member at a time. The archive iterator owns its disposal. Cache clear intentionally does not sweep this shared directory: ownership and active leases are not recorded there. Existing interrupted archive children may require re-expanding the retained parent archive. A swallowed checkpoint failure must not be described as a durable child recovery guarantee.
- R2 holds immutable original/result/asset objects and upload session receipts. D1 is the authoritative owner-filtered document library. The deletion transaction removes D1 content and records a minimal reserved-ID tombstone together. Original insertion has an atomic `NOT EXISTS` tombstone predicate. Result CAS cannot update a removed row. Late captured assets and upload receipts recheck state and clean their own object keys.
- Deleting a document walks its object prefix and legacy global receipt listing in pages, checking both owner and document ID before mutating any receipt. This avoids loading the full list into memory, but work grows with receipt count. Request/platform failures return a cleanup retry, not a false success. A future indexed receipt registry and durable cleanup worker remain in #179.
- A worker terminated after writing an object but before its final deletion check can leave unreachable bytes until another deletion cleanup attempt. Tombstones prevent the document becoming readable again; this is not a proof of crash-atomic physical erasure across R2 and D1.
- Browser pickers often select files or one folder separately. Additive selections and supported multi-folder drops feed one queue. No arbitrary file cap, 50 GB result, unlimited capacity, native engine deployment, or device test is claimed.

## Evidence

Synthetic `test-workspace-storage.mjs` uses in-memory IndexedDB transactions, two module instances, owner separation, failed writes, and refresh reads. `scripts/test-site-lifecycle-workers.mjs` uses disposable local Miniflare D1/R2 bindings, forced completion barriers, pagination and injected cleanup failures. Existing upload, workspace and new intake/control suites cover the adjacent contracts. These are source-level tests, not live Site/iPhone/iPad tests.
